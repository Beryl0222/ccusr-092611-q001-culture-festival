# 华服活动编排台说明

华服活动编排台需要在多方参与、事件顺序不稳定和服务重启的情况下保持记录一致。

## 核心约定

- 每条节目记录有所属方、状态（pending / approved / published）和递增版本，所有状态
  变化写入事件表；被接受与被拒绝的变更都留痕，现场可核对"哪一次调整已经生效"。
- `request_key` 抵御重复提交：同一键只产生一次结果（成功或失败都缓存重放），
  因此同一意图的重试可安全重发，而修复后重新发起的请求必须使用新键。
- 写操作在单条 `BEGIN IMMEDIATE` 事务内完成；冲突检测、门控校验和事件写入同生共死，
  失败时整次写入回滚。
- 审批与安全确认按节目版本收集：新版本意味着新的协调轮次。
- 发布是当天全部已编排节目的整体动作：存在未集齐确认的节目或场地时段重叠即拒绝；
  冲突结果逐对指明场地与受影响节目。
- 撤回必须填写原因；撤回后恢复该日期最近一次被取代的发布快照，快照冻结节目版本与
  时间，恢复时若工作版本又有更新会在 `version_skew` 中提示偏差。
- SQLite 文件即全部状态，服务重启后审批、发布与幂等记录均保留。
